# 高さ固定・水平移動による床校正の撮影

台座に取り付けたチェッカーボードを、同じ基準点の高さを保ったまま左右・前後へ移動して撮影します。基準点の3D位置と実測高さを保存し、後で床に平行な座標系を求めるための撮影ツールです。

## この実機の設定

- 白黒のマス：横10 × 縦7
- 検出する内側コーナー：横9 × 縦6
- 1マス：22mm（2026-10-06に再測定）
- カラー撮影：1440p（2560×1440）、30fps。画面は縮小表示し、格子は元の解像度で検出。
- 高さの基準点：白黒格子の下端中央（余白を含まない）
- 床から基準点までの鉛直高さ：1017mm（101.7cm、2026-10-06に実測）
- base：`000522521612`
- aux：`000535121612`（上下逆さま）
- 同期役割は接続端子から自動判定。現在はauxがMASTER、baseがSUBORDINATE。

設定は [`floor_capture_config.json`](floor_capture_config.json) にあります。実測高さ1017mmを登録済みです。高さを変えた場合は設定を更新するか、`--height-mm 実測値` で指定します。設定を `null` にすると起動時に入力できます。

## 起動

このPCの64-bit Pythonに `numpy`、`opencv-python` または `opencv-python-headless`、標準GUIの `tkinter` が入っていること、`build_2cam_x64` に `k4a.dll`、`depthengine_2_0.dll`、`export_kinect_rig_calibration.exe` があることを確認します。既存のKinectアプリを終了してから起動してください。

基準点を先に画面で確認する場合：

```powershell
.\capture_floor.cmd --preview-only
```

基準点は**白黒格子の外周の下端中央**です。10×7マス、22mmの場合は、格子の左端から110mmの位置にあたります。余白や台紙の下端を含めず、格子の下端中央に印を付けます。

画面の黄色い `REF BOTTOM` がその印を指すことを両画面で確認してください。上下を整えたプレビュー上でボードの下端を選ぶよう、交点の検出順を自動で揃えます。ボードの上下が画面でも正しく表示されるようにし、必要ならA/Bキーで基準にする辺を反転します。

撮影を始める場合：

```powershell
.\capture_floor.cmd
```

登録済みの1017mmを使って撮影画面が開きます。高さは床から白黒格子の下端中央までの鉛直距離です。台座の高さやボードの上下の傾きを変えて基準点の高さが変わった場合は再測定し、`--height-mm 実測値` で指定してください。

## 画面の操作

| キー | 操作 |
| --- | --- |
| C / Space | 現在の画像ペアを保存 |
| A | auxで基準にする辺を上下反転 |
| B | baseで基準にする辺を上下反転 |
| ＋ / －、明るく / 暗くボタン | 画面の明るさを調整 |
| Q / Esc / ウィンドウを閉じる | 終了 |

キー操作は撮影画面にフォーカスを合わせて行います。A/Bは最初の保存前に使い、**両方の黄色いREFが白黒格子の下端中央の同じ印を指すこと**を確認してください。最初の保存後はA/Bによる基準辺の切替を固定します。各位置で基準点の表示も確認し、基準辺の設定を変更する場合は新しい撮影セッションを始めます。実物のボードは、基準点の高さを保って左右に向きを調整できます。

auxは画面上で180度回転して正立表示します。保存する画像と3D座標は実機の元の向きで記録し、実機のカメラ校正値と対応させます。

## 撮影の進め方

1. 基準点に印を付け、床からの高さを測る。
2. 台座の高さとボードの上下の傾きを固定する。
3. 両方のカメラに格子全体が見え、画面の両方が `OK` になった状態で静止する。
4. Cを押して1組保存する。
5. 左右・前後に位置を変え、必要に応じてボードを左右に回して両方が `OK` になる向きへ調整し、静止して保存を繰り返す。

左右の向きは各位置で調整できます。ボードの姿勢を画像ごとに推定しているため、**同じ下端中央の高さ1017mmを保つこと**が条件です。床と垂直な軸の周りに首を振るように回し、前後に倒す・左右に傾ける操作は避けます。両画面の黄色い丸が同じ印を指すことも確認してください。

移動量はまず10〜20cmずつ、両カメラで検出できる範囲を使います。各位置で両方のカメラに格子の正面が見える向きへ調整しながら、左右と前後に撮影位置を広げてください。

**一直線に並ばない3か所以上**で撮影します。面内に広く分布した位置を使い、各位置で複数組撮ると、後で高さのばらつきを評価できます。同じ位置で何枚撮っても、床の向きを求めるための位置の広がりにはなりません。

格子が見つからない、再投影誤差が設定値を超える、取得時点ですでに古い画像の場合には保存しません。フレームの対応付けは時刻の差を直接確認し、1フレーム分のずれを同期位相だけで許容する処理にはしていません。

Cを押すと、画面で検出済みの同期画像ペアを保存します。格子の検出処理に時間がかかっても、その処理時間だけで保存を拒否しません。保存JSONには処理開始時の画像の経過時間と処理時間も記録します。

撮影中は両カメラの露光を同じ手動設定に揃えます。初期設定は30000µsで、実機SDKでは33330µsに丸められます。起動時に2台の実際の露光時間が一致することを確認し、終了時に元の露光設定へ戻します。

画面には明るさ補正も加えています。＋/－キーや「明るく」「暗く」ボタンで表示を調整できます。表示補正は保存画像や検出コーナーの座標を変更しません。

`REF BOTTOM waiting for grid` は基準点が未検出の状態です。両カメラに格子の正面が見えるようにボードを2台の中間方向へ向けてください。格子を検出すると、下端中央に黄色の丸と `REF BOTTOM` の文字を表示します。

斜めから映る22mmの格子を検出できるよう、撮影は1440pにしています。必要なら `color_resolution` を `720p` / `1080p` / `1440p` から選べます。内部校正値も選んだ解像度に合わせて実機から取得します。

## 保存されるもの

```text
floor_calibration_images/<日時>/
  session.json
  rig_calibration.json
  base/0001.png
  aux_color/0001.png
  base_depth/0001.png
  aux_depth/0001.png
  captures/0001.json
```

- `session.json`：実測高さ、格子寸法、基準点、シリアル、同期役割、保存枚数。
- `rig_calibration.json`：その実機・撮影モードで取得した内部校正とcolor→depth変換。
- カラーPNG：注釈や表示回転を加えない元画像。
- 深度PNG：16-bit、値の単位はmm。
- 各組のJSON：フレーム時刻、同期誤差、検出コーナーの元画像座標、ボード姿勢、両カメラでの基準点の3D位置、aux→baseの変換。

下端中央の位置は検出した格子の寸法と姿勢から求めます。内側交点から22mm分をボード面に沿って延長するので、ボードやKinectの傾きも反映します。

撮影データはGit管理から除外しています。撮影後は、以下の手順で床への変換と2台の位置合わせを計算できます。

## 撮影後の校正と追跡

撮影画面を終了してから実行します。`<撮影日時>` は保存先のフォルダ名に置き換えます。

```powershell
python tools/calibrate_floor.py floor_calibration_images/<撮影日時> --output calibration/floor_calibration.json --template track_config_2.json --config-out track_config_2_floor.json
.\build_2cam_x64.cmd
.\track_floor.cmd
```

今回の2026-10-06の撮影結果は、`calibration/floor_calibration_20261006.json` と `track_config_2_floor.json` に反映済みです。起動は **`track_floor.cmd`** です。BASEの光学中心を床へ鉛直に下ろした点を原点として、XはBASEの右方向、Yは床からの高さ、ZはBASEが見る前方向を表します。単位はmmで、床面のYは0です。追跡対象は既存設定と同じ右耳です。

2台の実際の位置関係を校正してから、出力だけ床座標へ変換します。画像投影と追跡の統合には実際のカメラ間変換を使います。AUXのbody trackerには `flip180` を渡し、AUXの表示も正立させます。PTU設定は元の設定を引き継ぎ、今回のプロファイルでは無効です。

画面とコンソールに `BASE FLOOR [mm]` の座標が表示されます。`floor_tracking/<起動日時>/coordinates.csv` に、選択した出力の `x_mm,y_mm,z_mm`、BASE床座標、仮想90度AUX座標、取得元とbody frameの時刻を保存します。同じフォルダの `config.json` はその実行の設定のコピーです。座標が検出されないフレームにはCSV行を追加しません。撮影画像と追跡CSVはGitに含めません。

仮想90度のAUX座標を画面・コンソールの出力にする場合は、`track_config_2_floor.json` の `coordinate_output_frame` を `aux_floor_90` に変更します。原点はAUXを床へ鉛直に下ろした点で、Yは床からの高さ、ZはBASE床座標の+X方向、XはBASE床座標の−Z方向です。2つの床座標系の向きは厳密に90度になり、同じ物理点を変換できます。CSVにはどちらの座標も入るので、通常は `base_floor` のままで使えます。

今回の5か所では基準点の平面残差RMSが約0.50mm、両カメラの格子位置合わせRMSが約6.09mmでした。これはデータ内の整合性で、絶対位置精度の保証ではありません。カメラを動かした場合や、格子寸法・基準高さを修正した場合は再撮影・再校正します。

## 接続・保存の確認

```powershell
.\capture_floor.cmd --check-devices
.\capture_floor.cmd --smoke-test 5
```

`--smoke-test` は格子検出や高さ入力を要求せず、ハードウェア確認用の画像を1組保存します。`smoke_...` のフォルダと `dataset_kind=hardware_smoke_test` で実際の床校正データと区別します。`--preview-only` は画像を保存しません。
